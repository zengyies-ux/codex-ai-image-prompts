# 海外 AI 短剧视觉资产提示词工作台

这个项目把剧本快速转换成一套精简、可执行、具有明确美术设计的场景、角色、道具与封面图片提示词。

统一流程：

剧本通读 → 共享事实提取 → 分模块资产核验与去重 → 用户决定制作范围 → 中文标题 + 英文提示词 → 质检与反馈回写

默认只写提示词，不自动生成图片。

本工作台另有 [明亮写实卡通风格项目](风格项目/明亮写实卡通/README.md)。任务明确要求动画质感时先选择该风格分支，再沿用剧本通读、资产去重和分模块交付流程；默认写实仿真人路线不变。

## 零上下文 AI 启动协议

第一次进入本项目时，不要遍历所有历史剧目，也不要把示例成图当成新任务要求。按以下顺序开始：

1. 读取根目录 `AGENTS.md`，确认全项目硬规则与优先级。
2. 读取 `.agents/skills/drama-image-prompts/SKILL.md` 和根目录 `项目记忆.md`。
3. 判断用户当前处理的是新剧目还是已有剧目；已有剧目只读取该目录的 `剧目状态.md`，不要读取其他剧目的剧情文件。
4. 完整通读当前剧本一次，建立共享事实账；人物、地点、时间、服装变化和关键道具只提取一次，供四个模块复用。
5. 识别当前处于“解读／列资产／写提示词／看成图反馈／实际生成图片”中的哪一步。默认只交付提示词；只有用户明确要求生成图片时才实际出图。
6. 只读取当前模块对应的 reference，不一次加载全部规则。历史 `core-memory-v4.1.md` 不作为执行入口。

优先级固定为：**用户当前要求 → 当前剧目已确认事实与状态 → `AGENTS.md` → 技能与对应 reference → `项目记忆.md` → 历史案例**。发现冲突时按此顺序执行，并把真正稳定的新偏好回写到项目。

## 用户通常需要什么

| 用户的说法或资料 | 实际任务 | 默认下一步 |
| --- | --- | --- |
| “这是新剧本，先看看” | 剧本解读 | 通读全文，建立事实账并给出当前重点模块的精简资产表 |
| “没有资产表，你来列” | 资产拆解 | 只列实际需要制作、可复用的最小完整清单，用户决定最终范围 |
| “先做场景／角色／道具” | 单模块生产 | 读取该模块规范；已有明确范围时直接写提示词，没有范围时先列极简清单 |
| “这张成图哪里不对” | 成图复盘 | 先观察实际图片，区分构图、身份、服装、材质、光影、文字或状态问题，再定点修改提示词 |
| “做 S01” | 场景状态编辑 | 先确认对应基础成图已获认可；提示词锁定原图，实际编辑时必须上传该基础图 |
| “设计两套服装” | 角色造型 | 用户要求的“两套”就是最终两套，不扩成四套；方向宽泛时先为这两套各给清楚中文概念。核心四角无脸模时可先做标明假设的概念，完整英文角色板提示词等待人脸参考 |
| “做道具图” | 道具资产 | 先判断制作或复用，再写 4:3 白底多视图提示词 |
| “做封面” | 高密度封面设计 | 需要准确英文剧名和要使用的核心角色人脸；先给 2—3 个明显不同概念，再写完整提示词 |

用户最低必需输入通常只有：**剧本＋当前优先模块**。用户明确要求概念测试时，一份自洽的独立角色简报也足以先做标明假设的中文概念；不能据此越级交付需要脸模和完整事实的最终角色板。已有资产表、成图、角色脸模、封面姿态和准确文字按任务提供；缺少资料时先完成不依赖它的工作，只在缺失内容会实质改变结果时提问。封面的人脸参考必须明确；姿态参考仅在用户提供或要求锁定具体动作时使用，不是默认必需项。

> **Snn 状态帧硬规则：** A01-S01、A02-S01 等状态帧必须在基础空间成图后制作，并以上传的基础成图为唯一参考。锁定原图的机位、构图、空间、固定家具和材质，只编辑时间、光线、窗帘或有限剧情物件；Snn 不是新的独立场景设计。

## 新剧目快速开始

1. 复制 模板/新剧目 到 剧目/剧名。
2. 将用户原始剧本、已有资产表、角色面部参考和封面姿态参考放入 00_输入；原始文件不覆盖。
3. 通读完整剧本并建立共享事实账，再按任务填写极简的场景、角色或道具资产表。
4. 有用户资产表时保持原有简单布局、名称和顺序；没有时按对应模板自行建立清单。
5. 用户决定实际制作范围后，再写对应模块提示词；Snn、主角色服装板和封面分别等待所需参考图齐全。
6. 每轮反馈写入 08_反馈记录；只有跨剧稳定偏好才更新根目录 项目记忆.md。

    剧目/剧名/

    ├── 02_场景提示词.md
    ├── 03_角色资产表.xlsx
    ├── 04_角色提示词.md
    ├── 05_道具资产表.xlsx
    ├── 06_道具提示词.md
    ├── 07_封面方案与提示词.md
    ├── 08_反馈记录.md
    ├── 剧目状态.md
    └── 99_归档/（只有出现旧版本时创建）

每个模块只保留一个当前资产表或提示词文件。旧版进入归档，不在根目录继续累积 v001、v002、v003。

重构前已经存在、且仍被现有对话或交付路径引用的校准剧可以暂时保留原位置，但必须在该剧的 `剧目状态.md` 中明确标为历史文件，不能作为新任务入口；正式迁移时再统一放入 `99_归档`，避免提前移动导致旧链接失效。

资产表是给制作团队看和贴图的，不承担内部审计。剧本依据、去重理由、状态判断和制作进度留在剧目状态或工作记录中，不能把表格做成复杂数据库。

## 场景编号

- A01：第一个大场景的核心母版。
- A02、A03：同一大场景内有独立空间功能的延展。
- B01：第二个大场景的核心母版。
- 同一机位只改变时间、天气、灯光或陈设时，默认不建立新编号。若该状态在剧本中实际发生、差异对剧情必要且一张底图无法兼容，或用户明确要求独立状态图，使用 `<基础空间ID>-S01` 作为状态帧，例如 A01-S01、A02-S01；S 序号按各基础空间分别递增。
- Snn 只能在对应基础空间成图后制作：上传基础图作为唯一参考，锁定原图构图、空间和固定陈设，只编辑时间、光线、窗帘或有限剧情物件。它不是第二张独立设计的场景提示词。

母版本身就是一张实际需要的场景图，不额外增加展示型大全景。

其他模块使用独立编号：

- `C01-L01`：角色 C01 的第 1 套服装造型。
- `G01`：第 1 组群演或功能角色。
- `P01`：第 1 个道具资产。
- 封面使用“概念 01／02／03”讨论方向，不与资产编号混用。

## 快速取舍

场景资产不是逐镜头分镜。一张资产是一块可复用的功能空间底板，可以承载该空间内多个相近动作与摄影角度。

问一句：

这张图是否提供了上一张无法提供、而剧情确实需要的新空间功能？

- 是：保留为延展或新大场景。
- 否：复用现有场景。

不同房间、功能区、室内外、车内外通常保留。普通反打、左右偏移、轻微移机和同机位状态变化通常合并。

不能因为两个空间属于同一栋楼或戏份较少就合并。例如工位区与老板办公室都在剧本中实际发生剧情时，应分别保留。

剧情事件不同或观察方向变化本身不产生新资产。只有关键动作依赖原图中不可见的结构或功能区时才拆分。相同固定地址或建筑综合体沿用同一字母；独立地址、交通工具或独立城市环境开启新字母。

有用户资产表时，不直接删除条目。先在内部核验记录或对话建议中标记“保留、合并、待确认、补充”；用户确认后再更新极简最终表，不把管理状态列留在团队资产表中。

## 场景提示词格式

    A01｜中文大场景｜中文具体场景

    English prompt...

正文直接描述可见画面，不解释生成任务。每条应包含空间结构、构图、动作区域、材质、少量叙事细节、真实光源、色温、体积光、Hex 色板和必要硬限制。

默认硬限制：

- 空镜，无可见人物、背景人群、剪影或人形反射。
- 无宗教元素。
- 所有相关车辆、电子设备、包装、酒瓶、设施和标识采用无品牌设计，无可识别 LOGO、商标或品牌字样。

角色、道具和封面使用各自模板：角色为 16:9 服装板或群演组，道具为 4:3 白底多视图，封面为 3:4 带准确英文剧名成品。它们不继承场景空镜要求。

角色服装设计重点是服装、发型与首饰的共同叙事。海外角色先按国家、具体城市／地区、季节气候、交通、职业、收入、场合和目标市场建立当地生活基线，再加入角色专属偏离与剧情阶段；不能把中文互联网常见的泛化“欧美高级感”套在海外脸模上。女装在所有视图和自然动作下必须完整、稳定、非透视地覆盖胸部；设计感来自轮廓、层次、材质、结构、肩背、腰线和单一视觉焦点，不依赖低胸，也不靠统一厚重衣物解决覆盖要求。
