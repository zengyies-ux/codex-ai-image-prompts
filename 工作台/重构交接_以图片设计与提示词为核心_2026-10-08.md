## 5. 具体重构要求

### A. 入口按设计任务路由

支持三种主要输入，并保持混合输入自然可用：

| 输入 | 应采用的路径 |
| --- | --- |
| 文字需求、单张设计、小范围修改 | 明确当前模块、用途和必要条件，直接设计与写提示词 |
| 用户参考图 | 确定参考职责，实际看图，按要求还原、转译或改版，再交付提示词 |
| 指定剧目或完整剧本资产任务 | 按需进入该剧资料，核验共同事实与来源，再执行模块任务；整剧资产规划仍遵守用户确认范围后分批制作 |

“独立设计”不等于允许臆造剧情。如果用户要求与某部剧一致，仍需核对有关角色、事件、场合和已确认身份。缺少会实质影响交付的信息时再问；低影响的设计选择可标明必要假设后完成。已有充分输入或明确方案时，直接交付，不重复审批。

首次处理完整剧本制作任务时保留通读与完整性要求，建立可复用的解读；后续采用已有解读要核实版本、覆盖范围和相关原文，不能声称自己读过未读取的全文。不要把孤立小需求升级为全剧核验任务。

封面可以依据充分的独立设计简报工作；仍需准确剧名和任务所需的人物身份、关系信息。构思阶段资料不足应区分假设，正式交付不能凭空编造用户剧名或剧情。

同步修改技能描述、根入口、模块“最低输入”、模板和小白说明中真正具有普遍门槛作用的语句。应靠明确适用范围消除冲突，不能只在 README 加一句宽松规则、下游仍要求所有任务必须先读全剧。

### B. 隔离剧目资料，保护已有成果

核心工作台负责设计方法与提示词交付；`剧目/` 负责具体作品的剧本、解读、资产和该剧反馈；`设计参考/` 与风格资料负责按需参考。

优先用清楚的目录入口、职责说明、阅读边界和指向现有文件的链接实现隔离。不要为了目录整齐搬动大量既有资产，也不把历史剧目从仓库删除。

为剧目区提供简明入口，帮助 AI 识别“用户指定了哪一部剧、现有资料从哪里进”。未指定剧目时不要按最近修改时间猜测用户在做哪部剧，也不自动调用某部剧的人脸、季节或服装偏好。

现有状态文件有新旧进度混写等问题，可以记录具体位置和影响；本次不以清理所有历史状态为交付前置条件。维护当前任务必要的正确性即可。

### C. 精简规则，区分约束、方法与经验

逐模块检查重复要求、相互矛盾的要求、隐含的审美模板和不必要的固定流程。根据作用区分：

- 用户指定、已确认身份和必要制作约束：在适用范围内严格执行。
- 设计方法：提供选择、判断与修正办法，不变成每张图都要填满的清单。
- 历史经验：标明来源、任务条件与证据等级，一次成败不能扩展为永久公式。

共用要求保留一处维护来源，模块只补充自己的条件。历史失败稿可保留追溯，但不应被入口当成现行规则。按需读取风格分支与案例，减少为写一条提示词而读完整项目的负担。

以下既有制作能力与底线要保留：

- 用户范围和资产来源映射；不静默删除、合并或改名用户清单。
- 提示词完成、图片已生成、用户已认可分别记录。
- 场景资产默认 16:9 空镜，沿用现有空间编号；Snn 是获认可基础图的状态编辑。文字可在认可后预写，实际编辑必须用该基础图为唯一图像参考，并锁定规定的结构与机位。
- 角色服装 Cnn-Lnn、群演 Gnn；正式服装板与 9:16 审美试装各自的现有规格、身份参考职责和连续性。
- 道具 Pnn、默认 4:3 白底多视图；不把所有随景普通物件都升级成独立资产。
- 封面默认 3:4，准确完整英文剧名，人物身份和剧情边界；创意探索与用户已选定方案使用不同交付路径。
- 女性服装在所要求的视角和自然动作下不露乳沟、侧胸或胸部透视；通过实际领口、内衬和固定结构落实，保留设计吸引力。
- 不出现宗教元素、可识别第三方品牌、现实国家国旗／国徽／官方国家徽记；核验过且有画面用途的原创虚构机构标识和剧情文字可用。
- 默认写实仿真人；动画分支按需启用；四模块的空镜、空手、白底、画幅等规格不能互相污染。
- 技术模型名、固定焦段和生成参数不成为创意流程的硬门槛；保留影响实际交付的必要格式信息。

“抓眼”不强制动作、撞色、道具、夸张装饰或复杂字体。封面中的遮字、灰度等检查应有适用条件，不能否定本来就依赖色彩或标题共同构图的有效方案。简化规范时检查这类僵化的淘汰条件。

### D. 让参考理解真正进入设计

从现有方法收敛出一条可操作、轻量且有弹性的设计过程：理解用途与需求 → 观察具体视觉关系 → 构思有实质区别的整体方向 → 比较取舍 → 转成清楚的提示词。局部修复、忠实反推和已获认可方案无需重新走完整探索。

实际使用图片参考时，要求能够留下少量准确、可核对的记录：

1. 看到的具体证据：长度与体量、构图位置、色块、材质、轮廓、光线或空间关系。
2. 各部分怎样配合，以及这种解释的不确定性。
3. 本次保留什么、为用途或审核调整什么，调整后原来的视觉效果是否还成立。

必须真的打开并查看使用的图片，不能用文件名、图片描述、搜索摘要代替观察。记录应短，不要求用户每次阅读长篇鉴赏。用户明确要求反推或还原时优先忠实；要求融合与改版时再设计；参考身份图不能自动决定衣服、背景或人物性格。

自主构思要改变有意义的整体关系。换一个颜色、昂贵材质名称或多加一件饰品，不自动算新设计。也不要把所有方案都推向夸张、奇装异服或装饰堆砌。

四模块分别判断：服装看整体搭配与人物魅力；场景看空间性格、尺度与拍摄用途；道具看造型辨识、物理结构与剧情功能；封面看缩略图吸引力、类型和情绪表达。

小型案例索引仅在现有资料难检索时补充，优先链接原图、原提示词、用户反馈和适用范围。案例不是“温柔女主＝某几件单品”的检索答案，所有任务也不强制先看成功例。没有参考时仍可从需求出发独立设计；相关案例不足、陌生环境或连续失败时，再定向联网补充，实际看图并保留来源与适用条件，不盲目扩充图量。

用户所说“美式审美”要结合目标市场、题材、人物生活环境和用途，避免把它写成一套固定脸型、肤色、服装或配色。正式提示词使用可见设计语言，不靠品牌、作品或工作室名称代替设计。

- 比较改前改后阅读路径、重复规则和强制步骤，说明具体减少或保留了什么；不要为了降低字数牺牲关键能力。
- 小样可复制且适用，但设计判断仅为预判。没有新成图就不声称审美、点击率或生成一致性已验证。

测试是审阅与任务演练，不假称进行了真实的新对话、多代理或用户测试。无需为了验收新增复杂测试框架。

## 8. 同步发布与最终交付

先维护主项目规则，再依据 `导出/README.md` 同步受影响的场景和封面单文件指南、本地包、快速上手说明和 ZIP，更新发布版本与记录。普通聊天单文件仍是普通 Markdown，不要求安装 Skill。

独立包必须能在脱离本仓库、没有其他三个模块时使用；其任务路由同样支持资料充分的独立设计。历史参考作为可选资源，不能变成依赖主项目私有路径的必读内容。重建 ZIP 后实际解压，验证文件与发布目录一致，检查包内相对链接；保留可选风格分支按需读取。

最终只需交付：

1. 修改后的主项目入口、规范和必要模板。
2. 清楚的剧目资料入口及阅读隔离说明。
3. 一份合并的修改与验收记录，包含改动映射、三个小样、未解决问题与 Git 分支／基线。
4. 更新后的场景、封面发布物及简短上手说明。

最终回复用用户能理解的中文说明：现在如何开始设计、什么情况下读取剧本、参考图会怎样被使用、哪些验证已做、哪些仍需实际成图反馈。提供关键入口链接即可，不用罗列所有文件。

**从检查工作区与基线开始，先读现有规则，再按以上范围实际完成重构。维护项目的创造力、事实准确性与使用简洁度；不要把这份一次性交接任务书加入每次设计的必读链。**
