## 先选什么脸，再描述怎么拍

开始时复用当前完整剧本的事实账，确认年龄、人物关系、职业、性格与用户指定。人物表中的“外貌参考”须按其来源处理，不能自动升级为已锁定五官。已有角色编号就沿用；没有时使用剧本角色名，不占用服装的 L 编号。

先用一句中文明确观众应读出的气质与吸引点，例如“成熟稳重，眼神保留温度”或“清醒能干，放松时亲近”。需要探索时给少量有实质差异的选角方向；用户已选方向或要求直接写提示词时直接完成。

下面是可选择的描述维度，不要求逐项填满：

| 维度 | 描述可见关系 |
| --- | --- |
| 脸型与骨相 | 脸的长宽、颧骨与下颌的关系、下巴收拢程度；只强调决定该角色轮廓的部分 |
| 眉眼 | 眉形、眼型、眼睑与眼睛深浅位置；虹膜颜色与这些形态分开写 |
| 鼻唇 | 比例适中的鼻梁与鼻尖、上下唇的厚薄关系、嘴的宽窄；不把每个器官都设计成极端 |
| 发型 | 长度、分缝、顶部与两侧轮廓、卷曲程度、露出哪些眉眼；用完整描述减少发型名称歧义 |
| 常态神态 | 一种轻神态，以视线、眉头、眼睑或嘴角落地，留出后续表演空间 |

“漂亮、英俊、可爱”可以表达设计意图，同时写清支持这个方向的面部选择。保留年龄感与人物差别，不把所有角色统一成大眼、小鼻、尖下巴和相同浅笑。性格是表演方向，不能凭某种骨相断言真实人的性格。

摄影条件集中写清构图、一套光线、肤质与颜色。按年龄保留适度真实细节；儿童不套用成人的浓妆、胡根或深纹理。镜头名称是外观提示，不必强制指定型号或焦段。避免同时叠加多种互相冲突的摄影条件。

## 可改写的自然语言底稿

以下是本项目结合案例整理的原创骨架，**不是社区原文或效果已验证的配方**。填写后交付完整英文，不把占位符留给用户；顺序、段落与长度均可按人物调整。

```text
Create a realistic photographic identity portrait of an original fictional [age]-year-old [character description]. Use a vertical 3:4 composition, straight-on at eye level, with the complete hairstyle, both shoulders and upper chest visible against a clean white background.

[Describe the defining facial shape and a small set of coherent facial relationships.] [Describe hair color, texture and the shape of the haircut.] [Describe iris color and a subtle expression through the gaze, brows or mouth.]

The character wears [a simple upper-body garment]. Use gentle directional studio light with soft fill so the face remains clearly readable. Keep the complexion believable for the character's age, the color restrained and the eyes naturally reflective. One person, with no lettering, logos or watermark.
```

共同硬限制沿用共享基础，按实际可见内容落实。角色面部资产无需复述与画面无关的伤害、羞辱或其他剧情冲突；儿童描述温暖、适龄。无需堆叠长串敏感负面词。提示词中的画幅描述与生成端实际尺寸设置需要一致，写“3:4”本身不保证输出比例。

## 两个阶段分别处理

**原创选脸：**用文字交付独立候选。用户反馈图默认用于观察与修改源提示词；未明确指定为生成参考时，下一版仍写完整文生图提示词。文字不能保证多次生成同一张脸。

**定脸后扩展：**用户确认某张图为身份参考后，再在实际生成时使用该图。说明参考图负责身份，其他参考各自负责服装、发型或构图；列出本轮允许改变的内容。只改发型时保留五官与年龄，只改神态时保留骨相与身份。实际结果仍需检查身份是否漂移。

微调比较尽量保持其他条件一致，一轮集中解决一个问题；全新选角方向则可改变整体面部设计，不伪装成单变量修复。不要求为测试而调用出图；用户明确要求后才生成。

## 交付与验证

每位角色交付简短中文意图与一段可复制英文提示词，注明文字生成或参考编辑、版本和参考职责。记录“提示词已完成／已收到或生成图片／用户已认可”，正式锁定身份须有明确依据。

看图时先判断脸是否吸引人、年龄与角色是否成立，再检查五官神态差异、真实感和构图。亲属既要有共同面部关系，也要有独立身份；去掉服装色与发型后仍值得检查是否容易混淆。用户觉得普通或不好看时，先定位选角、文字表达或成图执行中的问题，不机械追加更多品质词。

本草案尚未证明能稳定产生符合用户口味或美国短剧观众偏好的面孔。后续实际认可的例子再用于调整方法；待确认阶段不自动同步到原模块、项目记忆或导出包。
