# 服装设计模块复核与改进

日期：2026-09-30。任务：接手服装模块，结合项目结构、实际评分与外部设计研究，定位“自然但缺乏吸引力”的原因并更新执行方法。本轮没有生成服装图片，没有新的用户评分，也不将规则更新记为审美效果已验证。

## 一、结论

项目已学会真实衣物类别、布料重量和穿着松量；尚不稳定的部分是**整套设计的开发与选择**。2026-09-25 的主规则已加入“沉稳也要有设计”和首饰同步构思，但辅助词库、研究记录和资产质检仍保留反向引导。新目标没有覆盖全部实际执行入口。

主要原因：

1. 性格和职业被直接换成单品公式。职业女主容易被写成短西装、长直裤或窄裙、低束发、小首饰；热辣权贵职场目标在构思时消失。
2. 细节数量替代整套判断。领口、腰省、纽扣容易凑到“至少三项设计”，却没有看得见的比例、色材和个人选择。
3. 转译过程只做减法。固定元素配额、首饰仅辅助、低位发型优先及降低秀场体量，使有效表达越来越弱。
4. 研究与交付之间缺开发。只读风格文字、直接写一个长提示词，再用抽象形容词证明它成立，缺少真正不同方向的比较和淘汰。
5. 修改只跟最新抱怨。加珠绣、换材料、加一个发夹，未必修好普通或错配的主体；需要持续保留完整简报。

这解释了用户为何能持续指出缺点：评价同时检查自然、抓眼、个性、场合和搭配完成度，不能只凭其中一项过关。评分不是装饰数量或曝光程度的线性结果。

## 五、现在的开发与淘汰方法

统一流程为：

**完整简报 → 实际查看相关参考 → 开发不同整套关系 → 同步组织衣物、妆发、首饰、鞋履 → 保住强度做可穿转译 → 比较淘汰 → 展开提示词。**

内部候选在整体比例、类别、色材、纹样或首饰组织上发生区别。单纯换色、改面料名称、加珠绣不算新方向。最终只交付用户要求的套数和形式，不为内部比较增加确认轮次。

筛选分别检查：

1. **吸引力与个性**：删除评价形容词后，仍能描述整套的可见选择；中景和全身都有连续信息。
2. **人物、场合与动作**：完整任务同时成立，工作／酒会／外勤不能成为抹去人物表达或忽视功能的借口。
3. **生成与资产一致性**：身份、比例、衣料物理、画幅、站姿、覆盖、饰件和各视图可执行。

成图改版区分设计选择、提示词表达、生成执行。普通或错配主体重构，关系失衡重组，已成立主体才补局部；不自动把每次批评变成全面加装饰或全面做减法。

## 六、复核与下一轮验证

本轮检查范围为现行服装源文件、角色资产标准、入口、模板及相关记忆；不从旧剧目或导出快照加载第二套规则。旧记录保留历史，不反写已完成提示词。场景和封面导出包不包含本次服装模块规则，不需要同步其发布快照。

三位子智能体分别完成规则一致性、评分证据和外部来源的第二轮只读复核。根据复核修正了可复制模板的规则相对链接、夜间社交与外勤的评分比较、来源标题与发表信息。现行八文件与本报告的本地 Markdown 链接已检查有效；模板不依赖原目录访问工作台规则。

静态复核要确保四种边界同时成立：

- 沉稳角色有完整设计，不默认低饱和套装、小首饰与低盘发。
- 允许熟悉衣物、单色和跨国共通穿法；整套关系需主动选择，不强制两处结构改造或地方符号。
- 高调角色保留热辣、财富表达与实际场合；胸部不露沟，资产空手中立站姿。
- 两套80分保留为有限机制证据，不宣称其他场合或男性已验证。

建议下一轮优先验证“沉稳都市职场”“热辣权贵职场”“高端私人酒会”三个条件，而非继续在已较顺手的自主私服中验证。使用对应已确认脸模、9:16 中立全身，并比较实际胸腰中景。按用户需求再设计，不在本轮自动增加服装或出图。

成功标准仍由实际成图与用户反馈决定：自然感保持，整套比例和色材／首饰关系清楚，人物与场合吻合。当前完成的是规则与工作方法改进，85分目标待验证。
