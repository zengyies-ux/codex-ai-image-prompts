# 场景资产工作流

## 一、先建立剧本事实账

通读完整剧本，不只读取场景标题。按集记录：

| 字段 | 内容 |
| --- | --- |
| 集数 / 场次 | 可定位来源 |
| 城市 / 地区 | 剧本明确或待推导 |
| 大场景 | 公寓、公司、机场等地点系统 |
| 具体空间 | 客厅、玄关、工位、走廊等 |
| 时间 / 天气 | 剧本明确、连续性推导或待定 |
| 实际动作 | 人物在此做什么 |
| 视觉证据类型 | ACT / VIS / MENTION / STATE |
| 复用关系 | 首次出现、再次出现、状态变化 |

证据类型：

- ACT：剧情实际发生在此，人物有动作、对话或关键事件。
- VIS：剧本明确需要插入、转场或视觉证明。
- MENTION：只在台词、旁白或电话中提及。
- STATE：已存在空间的时间、天气、灯光或陈设变化。

实际呈现的回忆、梦境、短插入和一小段剧情，也按 ACT／VIS 核验，不按时长或台词数量跳过。仅口述过去的事件仍是 MENTION；不能把“回忆画面”和“回忆叙述”混为一类。复用已有空间时记录对应资产；独立功能空间或关键动作需要原图不可见的结构时补充资产。

清单收尾时逐项检查现在时主线、实际可见回忆／梦境、短插入／转场及一场戏内部的空间转换；每项都映射到“已有资产／需要补充／待核实”，并写明依据。目标是完整覆盖实际画面，再减少重复资产，不用“最小清单”省略短暂但必要的空间。

## 二、有资产表时

1. 保留用户原始名称、顺序和来源编号。
2. 为每项补充剧本证据、时间、动作与复用关系。
3. 给出处理建议：
   - 保留：有独立剧情功能。
   - 合并：同空间、同画面用途，仅状态变化。
   - 待确认：资产表要求但剧本只提及，或用途不明确。
   - 补充：剧本明确发生但资产表遗漏。
4. 不静默删除或改名。范围存在实质歧义时先交付核验结果；若用户已经明确要求直接制作，或清单依据充分且不影响后续修改，可继续写提示词，不重复等待批准。

资产表中不同空间即使戏份较少，也不能仅因“用得少”而删除。判断核心是它是否承担独立视觉功能，而不是台词多少。

## 三、没有资产表时

从剧本事实账建立最小清单：

- ACT 默认进入清单。
- VIS 在无法由已有场景承担时进入清单。
- MENTION 默认不建图。
- STATE 默认并入已有资产的备注。

若一个具体空间可以同时承载多个连续动作，不为每个动作单独建图。

### 过渡空镜按用户需求制作

2026-10-03用户明确：后续不主动设计额外的过渡／时间流逝空镜，也不自动在资产表末行增设空镜组；只有用户主动提出需要时才列入制作范围。剧本中的时间跳跃可先记入事实账，不能仅据此追加空镜图片。此前已由用户指定的过渡组保留，不追溯删除。

这里的过渡空镜不同于“场景底图无人”：正常剧情功能空间仍按默认无人场景图制作，实际回忆、短插入的必要空间继续核验。

## 四、去重决策

先确认判断对象：这里拆的是“场景资产”，不是逐镜头分镜。一张场景资产应当能在同一功能空间内支撑多个相近镜头和动作。

依次回答：

1. 是否是同一个物理空间？
2. 是否是同一种画面用途，且关键动作不依赖新的空间结构？
3. 差异是否只来自时间、天气、灯光、陈设或道具？

三个答案都为是：合并。

观察方向变化本身永远不足以新增资产。剧情事件变化本身也不足以新增；只有现有图片看不到完成关键动作所需的独立结构或功能区时才拆分。

下列情况通常保留：

- 同一建筑中的大厅、办公室、会议室、走廊、厨房、卧室等不同功能区。
- 同一办公楼中的工位区与老板办公室，只要剧本实际进入并发生剧情，就分别保留；不能因为都属于“公司”而合并。
- 同一地点中，关键动作需要专门可见的结构，例如垃圾处理器、门口检查、车内手机操作。
- 室内与室外、车内与车外。
- 剧本明确要求的建立镜头、转场或视觉证据。

下列情况通常不新增：

- 普通反打。
- 入口左侧与右侧。
- 仅向前或向后移动几步的机位。
- 为展示美术而增加、没有剧情用途的大全景。
- 同一客厅的派对版、午后版、夜景版；只有状态在剧本中实际发生、视觉差异必要且一张底图无法兼容，或用户明确要求时，才建立独立状态帧。

## 五、建立场景家族与编号

- A 表示第一个大场景，B 表示第二个大场景，依次类推。
- 01 是该大场景最核心、复用率最高且有实际剧情用途的母版。
- 02、03 等是同一大场景内的必要功能延展。
- 下一个大场景从 B01 开始。
- 母版不是额外增加的一张图；从实际需要的具体场景中选一张作为 01。
- 同机位状态默认记入基础空间备注，不单独计图。只有该状态在剧本中实际发生、视觉差异对剧情必要且一张底图无法兼容，或用户明确要求独立状态图时，才建立状态帧，例如虚构占位示例 `A01-S01｜〔同一大场景名称〕｜〔基础客厅的夜间状态〕`；示例名称不是新剧事实。
- 通用语法是 `<基础空间ID>-Snn`。S 序号按每个基础空间分别递增：A01 的状态为 A01-S01、A01-S02；A02 的状态从 A02-S01 开始；B03 同理。
- S01 是依附原空间的生产帧，不占用 A02 这类功能延展编号。
- 状态帧的生产顺序是“基础提示词 → 基础成图并获用户认可 → 可提前预写 Snn 编辑提示词 → 实际编辑时上传该基础图作为唯一视觉参考 → Snn 图片编辑”。基础成图尚未获认可时只登记状态需求；已获认可后，写编辑提示词不要求用户为了文字再次上传图片。Snn 不能写成另一条独立文生图提示词。
- Snn 编辑提示词必须把对应基础图指定为唯一视觉参考，明确锁定机位、裁切、焦段透视、空间尺寸、建筑结构、窗型、固定家具、材质和位置关系，再单独列明允许变化的状态变量。若需要改变这些锁定项，该画面应重新判断为功能延展或新母版。
- 原资产表已有编号时，只在内部核验清单中保留“来源编号”映射；新编号用于统一生产与交付，来源映射不增加到团队最终资产表。

大场景字母边界：同一固定地址或建筑综合体中需要共享设计连续性的室内外区域沿用同一字母，例如酒店大堂、后勤走廊和门外雨棚属于 B 组；独立地址、交通工具或能够脱离主体建筑成立的城市环境开启新字母。

内部分析可以记录来源编号、剧本依据、时间、动作、证据类型、处理决定与母版关系，但这些字段不进入团队最终资产表。

最终资产表保持横向极简结构：

| 大场景名称 | 衍生场景01名称 | 图片 | 衍生场景02名称 | 图片 | 衍生场景03名称 | 图片 |
| --- | --- | --- | --- | --- | --- | --- |

编号直接写进衍生场景名称，例如 `A01 客厅／落地窗看海`。复杂核验结论写入剧目状态或工作记录，不增加审核、证据、优先级、负责人、版本等管理列。

## 六、定义母版设计 DNA

A01 确定同组延展共享的：

- 城市与当地建筑语言。
- 场景等级与人物生活层级。
- 主要材质家族。
- 四至八个 Hex 色值。
- 主光方向、色温范围与整体明暗关系。
- 一个可重复识别的视觉锚点。

A02 及后续延展继承这些设计 DNA，同时按自身剧情功能独立组织构图。同宅默认统一装修语言、等级和色材气质，不要求客厅、厨房、卧室互相可见，也不为展示连接额外增加房间或贯通门洞。只有剧本或用户明确要求跨房间视线、递物、进入／离开等动作关系时，才设计并核对所需连接；例如厨房里的人看向客厅中的人。其余空间不要求复原成可拼接户型。所谓光影家族，是灯具逻辑、对比度和整体美术气质相容；具体光向与色温必须服从本场景的真实开口、天气和剧本时间。

每个延展至少保留一个与母版可关联的线索，例如同类墙面材料、门框语言、地面铺装、窗景方向或灯具家族。关联线索用于识别同一地点体系，不用于制造无价值反打。

## 七、批次策略

一次完成一个大场景家族：

1. A01。
2. A02、A03 等全部必要延展。
3. 基础图未获认可时只登记必要的 Snn 状态需求。
4. 用户快速生成并确认基础空间设计。
5. 对已获认可的基础空间，可预写引用该图的 Snn 编辑提示词；实际执行编辑时再上传该基础图作为唯一视觉参考。
6. 记录反馈后进入 B01。

这种顺序比同时铺开多个城市和地点更容易发现审美、编号和结构问题。
